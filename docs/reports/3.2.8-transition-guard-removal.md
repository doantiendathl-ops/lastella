# Report: 3.2.8 Transition Guard Removal

**Status:** Complete  
**Branch:** phase-3  
**Date:** 2026-07-02

## Summary

Removed the aggregate room-charge transition guard and its associated helper methods; introduced a backfill Artisan command for retroactively posting per-night entries on existing checked-in stays.

## Changes

### FolioService (removed methods)
- `autoPostRoomCharge()` — posted single `ROOM_CHARGE_{id}_AGGREGATE` entry at check-in. Superseded by `RoomChargePostingJob` posting per-night `ROOM_NIGHT_{stay_id}_{date}` entries.
- `calculateGuardedFolioTotal()` — returned requirement estimate when aggregate key absent; raw sum otherwise. Superseded by `getFolioTotal()` (simple sum).
- `doPostRoomCharge()` (private) — inner implementation of the above.

### BookingService
- `finaliseBookingCheckout()`: replaced `calculateGuardedFolioTotal()` → `getFolioTotal()`.
- `paymentSummary()`: replaced `calculateGuardedFolioTotal()` → `getFolioTotal()`.
- `updateRequirement()`: lock check now queries `charge_type = ROOM` instead of the obsolete `ROOM_CHARGE_*_AGGREGATE` posting key. Added `ChargeType` import.

### New: `BackfillPerNightCharges` Command
- Signature: `folio:backfill-per-night-charges {--dry-run} {--date=}`
- Iterates CheckedIn stays; for each date between actual check-in and target date, posts a `ROOM_NIGHT_*` entry if not already present (idempotent).
- 4 tests: dry-run, backfill correctness, idempotency, skip-already-posted.

### Test Cleanup
- **FolioCrudTest**: Removed 5 tests for deleted methods; updated `test_balance_due_equals_total_charges_minus_paid_total` (uses factory entry) and `test_update_requirement_is_locked_after_room_charge_posted` (uses ROOM-typed entry).
- **RoomChargeHotfixTest**: Removed 4 aggregate-behavior tests (quantity=nights) and 2 obsolete tests (deleted method, behavior changed). Remaining 11 tests pass.
- **PaymentCrudTest**: Added `FolioEntry` factory call so `expected_total` has a concrete value (1 000 000) for the breakdown fields test.
